# 宜蘭活動頁：自動更新與編輯維護

本次實作位於 `codex/activity-ingestion`。策略為使用者確認的「官方來源完整就自動上架，其他待審」。部署採正式資料庫加欄位 migration，再啟用 Vercel 正式環境及排程；上架結果以正式 API、資料庫與瀏覽器驗證。

## 活動頁怎麼更新

保留現有活動卡片與投稿入口，補強內容供應與日期正確性。訪客先看到仍在舉行及即將開始的活動，再以未來七天、本月、下個月、類型與地點篩選；跨月展覽不因開始日在上個月而消失。活動詳情顯示資料來源與同步日期。後台增加「預覽抓取／立即更新／待確認活動」。

下一階段適合增加「今天、週末、鄉鎮」快速入口與編輯精選，但應先累積足夠活動，再調整首頁版面。不要用沒有來源的 AI 活動填滿頁面。

## 更新流程與判定

1. 每日台灣時間 06:00 的 Vercel Cron 排程呼叫受保護端點；實際觸發精度依平台方案。也可由管理員立即更新或使用 CLI。
2. 只讀取程式中核可的來源網址，不接受任意 URL；拒絕轉址、HTTP 錯誤、HTML 錯誤頁、超大資料與無法辨識的結構。
3. 將來源 ID、名稱、描述、日期、地點、主辦單位、來源網址及場次統一為候選資料。空缺保留空缺，不推測主辦單位、時間或費用。
4. 官方來源且必要欄位完整、日期合法、無暫定／取消／延期／多場次疑義，才自動上架。圖片不是上架必要條件；優先使用核可官方來源的活動圖片，無圖時使用既有類型圖示。宜蘭勁好玩的主辦欄可留空，其他來源仍須完整。
5. 同來源 ID 重跑不新增；跨來源同名同日同地點視為重複。名稱相近且日期重疊時轉人工比對，不直接合併不同活動。
6. 候選缺資訊時存入獨立待審表，允許空日期，避免以假日期塞入正式活動。管理員補齊後上架，或略過並記住此決定。
7. 自動管理的活動可跟隨來源更新；來源公告取消／延期或資訊不再完整時，退回待審。人工改過、退回或刪除的活動不被自動覆蓋或重建。
8. 不因一次抓不到活動就刪除既有活動；活動結束後由日期篩選自動退出近期清單，歷史資料保留。來源失敗會留在執行紀錄；部分失敗時其他來源仍可完成，Cron 回傳 503 便於平台監看。

文化部的同一活動可能跨縣市、場館與日期。只保留宜蘭場次，依場館分組；多場次會待審，避免把兩場音樂會誤當成連續十天的活動。

## 使用與啟用

無資料庫、無金鑰也可以先抓取預覽：

```powershell
npm run activities:preview
```

完整候選保存在被 Git 忽略的 `.cache/activity-import/preview.json`。

正式啟用順序：

1. 確認 `HOMESTAY_DATABASE_URL` 指向本網站活動資料庫。先驗證 migration，再套用；只新增欄位與匯入表，不更動原活動內容。

```powershell
node --env-file=.env scripts/migrate-activity-imports.mjs
node --env-file=.env scripts/migrate-activity-imports.mjs --apply
```

2. 將本分支部署到網站。Vercel 正式環境設定隨機 `CRON_SECRET` 及 `ACTIVITY_IMPORT_ENABLED=true`，已有的 `HOMESTAY_DATABASE_URL`、管理員認證設定照常使用。`CRON_SECRET` 不可放在 public runtime config、前端或版本控制中。
3. 管理後台 `/admin/yilan-activities` 先按「預覽抓取」核對，再按「立即更新」。檢查執行紀錄、實際公開詳情頁與來源連結。也可在確認環境後執行 `npm run activities:sync`，此命令會寫入資料。
4. 核對 Vercel Cron 首次正式執行結果。僅建置成功或 `vercel.json` 存在，不代表排程已啟用或正式站已更新。

停用自動更新時將 `ACTIVITY_IMPORT_ENABLED=false`；不影響既有活動瀏覽或管理員手動更新。資料庫 advisory lock 避免排程、手動更新、待審上架同時重複寫入。

[Vercel 官方排程管理說明](https://vercel.com/docs/cron-jobs/manage-cron-jobs)說明了授權標頭、部署、排程精度及執行紀錄。

## 驗證與邊界

```powershell
npm run test:activities
npm run activities:preview
npm run test:activities:db
node --test tests/*.test.mjs
npm run build
```

資料庫測試在獨立 schema、單一 transaction 執行，結束一律 ROLLBACK，使用自己的 identity，不消耗正式活動表序號。涵蓋新增、重跑、更新、取消、編輯保護、待審上架、跨來源去重、刪除／略過記憶、單來源失敗回復及真實來源資料寫入。

部署前手機預覽使用真實 Vue 元件與實際官方候選資料，連到隔離 transaction；正式站驗證如下。新的管理與排程 API 也納入未登入／偽造 cookie 拒絕測試。

目前沒有 Facebook／Instagram／售票平台爬蟲。這些來源須先確認可用的官方 API、RSS 或主辦單位授權，接入後預設待審。新增來源應擴充 `server/services/activity-sources.js` 的 registry 與 adapter、真實抓取一次、補上解析測試；不能讓 AI 自行添加任意網站或把非官方內容當成官方來源。

目前無來源消失即自動下架機制、無郵件／LINE 告警。圖片使用官方原始網址，不下載副本。來源明確取消可退回待審，來源直接移除活動則保留到活動日期結束；執行失敗需從後台或 Vercel 紀錄查看。人工接管的活動由編輯維護，來源快照仍更新，但不會覆蓋人工內容。
