## 同步失敗原因與處置

正式資料庫記錄顯示，10/17–11/4每天06:00的文化部回應持續缺少已知未結束活動；11/3、11/4有原始筆數證據：音樂8、展覽36、講座10。相較11/2晚間正式同步452／277／96，以及11/4白天正式預覽465／278／99，相同解析器在白天能讀取正常資料。錯誤已定位為排程時取得的上游資料不完整，並非前台篩選、宜蘭真的無活動或解析器完全不支援資料。

**證據界線：未取得文化部服務端內部排程或快取日誌，不能斷言上游究竟是清晨重建、快取節點或其他內部原因。**目前確認的是實際收到的原始集合劇烈縮小。日誌中有19次固定06:00結果與白天成功對照；詳細當日實測位於 `output/activity-expansion-20261104/`。

修復：

1. 文化部主要端點改為資料集[6478](https://data.gov.tw/dataset/6478)的 `SearchShowAction.do?category=…&method=doFindTypeJ`，既有來源ID及場館辨識碼不變。音樂／展覽／講座以原 `activityOpenDataJsonAction` 為第二個官方端點備援。
2. 對照最近14天成功來源的原始筆數高值；基準至少20筆而本次少於50%時視為異常。即使宜蘭仍有非零筆數，或講座本來沒有宜蘭已知活動，也不會把大幅縮水當成功。
3. 來源失敗、已知未結束資料卻零筆、原始筆數驟減皆觸發一次有界重試；重試仍異常則維持partial／failed並保留既有活動。記錄首次與重試的端點、筆數、內容雜湊及錯誤，避免丟失診斷證據。
4. 每日Cron從06:00移至10:00（UTC `0 2 * * *`），避開已連續觀察到異常的時段。改時間是依觀察採用的緩解，不是聲稱已掌握上游內部作業時間。
